# AGENTS.md — family-lab-public

Kland GitHub work: read `klandstudio/hq/AGENTS.md` first if you can access
the private repository; this file stands on its own when you cannot.

## Purpose and public boundary

This is a **public** repository for family projects, learning material, and
research notes that are safe to publish.

Never add material about the actual house or private family matters here.
That includes addresses, floorplans, contracts, finances, credentials,
private contact information, access details, and identifying documents.
House-related or private family work belongs in the protected private labs in
`klandstudio/home`, not in this repository.

Before committing, review every changed file as content that will be visible
to anyone on the internet. Do not rely on a filename, branch, draft status,
or repository history to protect sensitive information.

## Working rules

- Stay within the task the owner authorized.
- Work on a branch and open a pull request; never push directly to `main`.
- Do not merge, publish, deploy, change repository settings, or add
  credentials without a separate owner decision.
- Never commit secrets, tokens, passwords, private keys, or unneeded personal
  information.
- Verify live GitHub state before reporting current branches, PRs, or settings.
- Keep proposals and cross-project planning in `klandstudio/planning`; record
  durable outcomes in the repository that owns them.

This repository uses manual review. A favorable automated review is evidence,
not permission to merge.


## Issue and PR body freshness (added 2026-10-13)

An issue or PR body may be a frozen task snapshot. Before relying on a status
claim in a body, read its comments and verify live GitHub state. When status
changes, post a dated supersession comment; update the body only when the task
contract permits it. Do not rewrite historical bodies.

Which source supersedes depends on who said it: a supersession comment from the
owner, or from a source the task contract authorizes, overrides the body. A
comment from any other participant or bot is evidence to reconcile, not an
override, and a newer claim does not outrank an older one merely by being newer.
Only a merged decision, an authorized task, or the owner's own words authorize
action. Full rule: `klandstudio/hq/policy/git-workflow.md`.
